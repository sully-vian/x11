# x11

Type-safe OCaml bindings to Xlib: X's integer constants become variants and
typed masks, so that values X would reject don't type-check.

Documentation: https://sully-vian.github.io/x11/

## Building

The dependencies are locked in `dune.lock` and built by dune's package
management, compiler included: `dune build` is enough. Xlib's headers come
from the system (`libx11-dev` on Debian/Ubuntu, `libx11` on Arch).

- Tests: `dune test`. The integration tests need Xvfb, xdotool, xprop and
  xwininfo; `test/test_x` needs a running X server (`$DISPLAY`).
- Documentation: `dune tools install odoc` once, then `dune build @doc`. The
  HTML is in `_build/default/_doc/_html`.

## Library layout and testing

The code is split into two libraries:

- `x11_internal` (`lib/internal/`) holds the whole implementation: ctypes
  descriptions and the OCaml types with their conversion from C structs. It
  contains no hand-written C: the stubs are generated by ctypes. The types the
  public API exposes are concrete in it (`window` is `Unsigned.ULong.t`,
  `display` a ctypes pointer). It's a private library (`(package x11)` without
  `public_name`): dune installs it with the package, as
  `x11.__private__.x11_internal`, but other projects can't depend on it or
  open its modules.
- `x11` (`lib/`) is the public library. `x11.mli` re-exports what users need
  and hides the representation of `window`, `atom`, `time`, `display`, ...

Unit tests live in `test/internal/` and depend on `x11_internal`, so they see
the real types and can check every field without `Obj.magic`. They need no X
server: `dune test test/internal`. Tests in `test/` depend on `x11` and exercise
the public API: `test/integration/` runs them against Xvfb, and `test/typing/`
holds cram tests that check which code type-checks against `x11.mli` and
which doesn't.

`x11.mli` must keep declaring its types without equations to the internal ones
(`type window`, not `type window = X11_internal...`): an equation would make
the internal representation part of the public API.

## Usage notes

Comparing windows needs no helper: polymorphic `=`, `compare` and `Hashtbl`
work on `window`, because `Unsigned.ULong.t` provides its own compare and hash
functions.

## Unsupported event types

`next_event` raises `Failure "Unsupported type ..."` on any event type that
`Xevent_ctypes.xevent_of_c` doesn't convert yet: `KeymapNotify`,
`GraphicsExpose`, `NoExpose`, `VisibilityNotify`, `ResizeRequest`,
`SelectionClear`, `SelectionRequest`, `SelectionNotify`, `ColormapNotify`,
`GenericEvent`. Extension events (e.g. XRandR) arrive as `Unknown` and also
raise.

None of these arrives unless the program asks for it: each needs its event
mask selected (e.g. `keymapStateMask`, `resizeRedirectMask`), taking part in
selections, an extension, or for `GraphicsExpose`/`NoExpose` the program's own
`XCopyArea`/`XCopyPlane`, which isn't bound. A window manager that selects
`SubstructureRedirect` on the root and `StructureNotify` on its clients only
gets ported events.

## Towards the `sowm` example

`examples/sowm.ml` is meant to port [sowm](https://github.com/dylanaraps/sowm),
a small floating window manager, in one file. What it needs from the bindings:

Needed:

- [ ] `XSetErrorHandler`: sowm ignores every error, while Xlib's default
      handler exits on the first one (e.g. `BadWindow` for a client that just
      closed). Xlib calls the handler from C, which needs `ctypes.foreign`
      (libffi), a new dependency, or a narrower API (only "ignore all errors")
      with some C.
- [ ] `XSetInputFocus`, with a `revertTo` variant (sowm uses `RevertToParent`)
      and `currentTime`.
- [x] `XUnmapWindow`, to hide the windows of the workspace being left.
- [ ] `XKillClient`, for the close binding.
- [ ] `XkbKeycodeToKeysym` (from `XKBlib.h`), to find the binding of a
      `KeyPress`.
- [ ] `XDisplayWidth`/`XDisplayHeight` (with `DefaultScreen`), for centering
      and fullscreen.
- [ ] Turning a `ConfigureRequest` into `windowChanges`, to grant it with
      `configure_window`: `configureRequestEvent.value_mask` is still an `int`.
- [ ] Mask difference/intersection and equality, to drop NumLock and CapsLock
      from an event's `state` before comparing it with a binding (sowm's
      `mod_clean`).
- [ ] Check whether the X connection needs closing in a launched program
      before `exec`, as sowm does.

Can be left out or simplified at first:

- [ ] `XCheckTypedEvent`, only used to drop queued `EnterNotify`/`MotionNotify`.
- [ ] `XGetModifierMapping`/`XFreeModifiermap`, to find NumLock's modifier:
      `mod2Mask` almost always.
- [ ] `XUngrabKey`/`XRefreshKeyboardMapping`, to grab keys again after a
      keymap change. The latter takes the event back as a C struct, which the
      bindings can't write yet.
- [ ] `XDefineCursor`/`XCreateFontCursor`, which only set the root's cursor.

Already covered:

- [x] `XOpenDisplay`, `XNextEvent`, `XSelectInput`, `XMapWindow`,
      `XRaiseWindow`, `XMoveResizeWindow`, `XConfigureWindow`,
      `XKeysymToKeycode`, `XGrabKey`, `XGrabButton`.
- [x] `XMoveWindow` and `XGetGeometry`, through `configure_window` and
      `get_window_attributes`.
- [x] The XF86 media keys, through `string_to_keysym` (e.g.
      `"XF86AudioRaiseVolume"`).
- [x] Launching programs (`fork`/`execvp`, ignoring `SIGCHLD`), with OCaml's
      `Unix` and `Sys`.
