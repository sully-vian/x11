# x11

X11 bindings for OCaml

The goal is to provide a clean and type-safe OCaml interface to X11.

## Library layout and testing

The code is split into two libraries:

- `x11_internal` (`lib/internal/`) holds the whole implementation: ctypes
  descriptions and the OCaml types with their conversion from C structs. It
  contains no hand-written C: the stubs are generated by ctypes. Nothing in it
  is abstract. It's a private library (`(package x11)` without `public_name`):
  dune installs it with the package, as `x11.__private__.x11_internal`, but
  other projects can't depend on it or open its modules.
- `x11` (`lib/`) is the public library. `x11.mli` re-exports what users need
  and hides the representation of `window`, `atom`, `time`, `display`, ...

Unit tests live in `test/internal/` and depend on `x11_internal`, so they see
the real types (`window` is `Unsigned.ULong.t`, `display` a ctypes pointer) and
can check every field without `Obj.magic`. They need no X server:
`dune test test/internal`. Tests in `test/` depend on `x11` and exercise the
public API: `test/integration/` runs them against Xvfb, and `test/typing/`
holds cram tests that check which code type-checks against `x11.mli` and
which doesn't.

`x11.mli` must keep declaring its types without equations to the internal ones
(`type window`, not `type window = X11_internal...`): an equation would make
the internal representation part of the public API.

Comparing windows in user code needs no helper: polymorphic `=`, `compare`
and `Hashtbl` work on `window`, because `Unsigned.ULong.t` provides its own
compare and hash functions.

## Unsupported event types

`next_event` raises `Failure "Unsupported type ..."` on any event type that
`Xevent_ctypes.xevent_of_c` doesn't convert yet. Some of these reach a window
manager without being asked for, so they need porting before the WM can run
for long:

- `NoExpose`, `GraphicsExpose`: generated by `XCopyArea`/`XCopyPlane` when the
  GC has `graphics_exposures` on, which is the default.

Still unported: `KeymapNotify`, `VisibilityNotify`, `ResizeRequest`,
`SelectionClear`, `SelectionRequest`, `SelectionNotify`, `ColormapNotify`,
`GenericEvent`. Extension events (e.g. XRandR) arrive as `Unknown` and also
raise.
